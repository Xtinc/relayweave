# RelayWeave 缺陷改进计划

日期：2026-10-29。状态：A 批次已完成（01、02、10、13，28 项相关回归通过）；B–H 尚未实施。

本计划基于[架构与代码审视记录](架构与代码审视记录.md)、当前源码核实结果及用户补充的设计前提。当前重点是清理冗余：删除无生产用途的能力，合并重复实现，缩减多余层次和重复状态；功能修复与行为改造随后进行，多跳 TLS 放在最后。

## 1. 已确认的前提

1. **生产调用决定代码是否保留。** Agent、Node、dashboard 的实际业务路径没有使用、仅测试使用的能力，列为冗余清理对象。Node 中仅用于承接无人发起的协议处理分支，不构成独立的业务使用场景。清理时也检查 proxy 等生产调用方，避免误删共享能力。
2. **首先清理冗余。** 原审视记录第一部分是独立的清理任务，不因后续 TLS、UDP 或控制恢复改造而延后，也不改写成新增功能任务。抽取公共代码后删除原有重复实现，合并对象后删除原有薄包装；不以增加一层适配器或同时保留两套状态作为完成。
3. **Master 出站队列满导致停机是既定设计。** 保留有界队列、容量限制和满载失败语义。改进方向是控制正常业务产生的集群消息数量、准入和突发，不能通过取消队列、无限扩容或静默丢弃关键事务消息规避容量约束。
4. **多跳 TLS 应透明传输，但最后实施。** 当前节点间缺少该 TLS 层保护，存在业务载荷泄露风险；透明传输目标仍保留。由于握手、证书、接入和半关闭流程改动较大，当前不提前改造，也不将其设为其他清理工作的前置依赖。只给 NodeLink 增加逐跳加密，不等同于完成透明转发目标。
5. **分批、按项实施。** 按第 3 节批次推进，每批内按项修改、验证和更新相关设计说明；批次不是一次大范围提交，避免同时重写控制协议、数据面和所有生命周期代码。

|---|---|---|---|---|

| 02 | 冗余清理 | 合并 NodeConnectionMgr 与单主控连接生命周期 | 1.1① | 删除薄包装，保留原有重连、异常处理和排空行为 |

| 13 | 局部清理 | 移除默认高实时优先级并修正线程命名 | 2.6② | 处理条件性部署风险，不新增无依据的调优配置 |

## 3. 实施批次

规模和影响范围是基于当前源码的相对估计，不代表工期承诺。规模指涉及的模块和修改量；影响范围指变更可能改变的行为，包括协议兼容、生命周期、调度和数据热路径。10 和 13 的改动较小，但仍分别验证来源拒绝行为和线程调度行为。

| 批次 | 范围与批内顺序 | 预计规模 | 主要影响 | 前置依赖 |
|---|---|---|---|---|
| A：删除与局部清理（已完成） | 01 → 02 → 10 → 13 | 小～中 | 删除闲置协议/字段；合并 Agent 主连接所有权；局部授权和调度调整 | 无；10、13 可独立完成 |
| B：配对与跨域去重 | 03 → 04 | 中～大 | Node 数据端点的建立、激活、取消和排空；维持现有业务语义 | A 后实施；03 为 04 提供稳定的配对接口 |
| C：状态与报文去冗余 | 05 → 06 | 大 | 内部状态表示、事务序列化和跨节点协议兼容 | B 后实施；06 依赖 05 的状态关联 |
| D：控制面开销收敛 | 07 → 08 | 中～大 | 查询广播、事务准入/发送节奏、会话路由与计数 | 07 依赖 06；08 无新增功能依赖，沿用当前会话规则 |
| E：数据入口内存优化 | 09 | 中 | 数据热路径的分配、复制、内存计费与背压 | 复用 B 的端点结构，按 01 清理后的缓冲接口实施 |
| F：UDP 与收尾生命周期 | 11 → 12 | 大 | UDP 客户端归属、关联创建/回收，以及业务收尾期限 | 11 遵守 07 的容量预算；12 的 UDP 回收依赖 11 |
| G：主控闪断解耦 | 14 | 大 | Agent/Node 控制身份重绑定、服务归属和业务存活策略 | 复用 02、08、11/12 确定后的所有权、索引与清理规则 |
| H：多跳 TLS 透明传输 | 15 | 很大 | TLS 端点、证书信任、接入协议、就绪时序、半关闭与部署 | 最后实施，基于前批次稳定后的接口和生命周期 |

### A. 删除与局部清理（已完成）

- **执行：** 先删除无生产用途的能力（01），再合并单主控连接管理（02）；将小范围的拓扑来源校验（10）和线程调度/命名调整（13）在本批完成。10、13 各自独立修改和验证，不与其他项相互绑定。
- **边界：** 01 虽以删除为主，仍会改变协议可用范围；02 虽是合并包装，仍涉及启动、重连和停止，按中等生命周期影响处理。不能将整批都视为低风险改动。
- **出批条件：** 闲置能力及对应测试已清理；原有识别、重连、取消与排空行为通过回归；正常 Master 快照可用、非 Master 快照被拒；线程默认调度和名称符合预期。

### B. 配对与跨域去重

- **执行：** 03 先删除 Stream/Datagram 的重复配对管理，再基于稳定接口实施 04，合并连续跨域操作。两项分开验证，以便区分配对状态错误与执行时序错误。
- **边界：** 本批不改变 UDP 客户端模型，也不引入端到端 TLS 或控制断线存活能力。
- **出批条件：** TCP/TLS/UDP 的准入、attach、激活、半关闭、取消和停止排空保持正确；重复实现和多余跨域接口已删除，并记录跨域次数变化。

### C. 状态与报文去冗余

- **执行：** 05 先按当前 wire 协议完成状态强类型化并验证，再由 06 缩减事务报文；不要同时修改某个模块的内部表示和 wire 语义。05 可按 NodeLinkMgr、Router、AgentSession 分步完成。
- **边界：** 05 保持 wire 行为；06 单独记录字段和兼容变化，同时调整发送、接收和校验，不长期保留 JSON/结构体两套状态。
- **出批条件：** 运行时重复解析和事务路径克隆已移除；准备、提交、关闭、失败回滚、重复和迟到报文回归通过，协议部署边界明确。

### D. 控制面开销收敛

- **执行：** 07 在精简报文上测量消息预算，收敛广播及突发；再实施 08 的查找索引与准入计数，分别比较发送行为和分派耗时。
- **边界：** 两项是分开的改动；07 调整流量与准入行为，08 维持同一业务语义。队列满停机策略保持不变，08 不等待未来的 UDP、primary 或 TLS 改造。
- **出批条件：** 有允许并发下的消息预算和队列高水位结果；过载仍按设计处理；重复请求、双角色、取消分派、关闭占额和索引回收正确。

### E. 数据入口内存优化

- **执行：** 单独实施 09，针对当前数据入口测量并减少复制、大协程帧和无效分配，不等待 TLS 改造。
- **边界：** 不与控制协议、会话索引或 UDP 生命周期调整混在同一次改动中，便于判断性能与内存变化的来源。
- **出批条件：** 修改前后的小包、大流量、慢接收端结果可比较；内存计费和背压仍有界，取消及半关闭行为正确。

### F. UDP 与收尾生命周期

- **执行：** 11 先完成多客户端关联和双向归属，再实施 12 的 UDP 活动跟踪与空闲回收。12 中 TCP/多跳 Finished 收尾期限可独立验证，不依赖 UDP 功能完成。
- **边界：** 本批开始改变客户端可观察行为；新增关联数量、创建节奏和空闲回收都要遵守 D 的控制面预算，并同步维护 08 的索引与计数。
- **出批条件：** 多客户端不串包；空闲、离线、超时和取消能释放关联与配额；迟到事件不复活会话；正常半关闭继续排空。

### G. 主控闪断解耦

- **执行：** 单独实施 14，先明确宽限期、恢复、重绑定和失败清理语义，再联动 Agent/Node 实现。
- **边界：** 本批改变控制断线后的存活策略，不能与 A 的对象合并同时进行，也不承诺 Master epoch 变化后旧业务存活。
- **出批条件：** 符合条件的 ready 业务可跨短暂控制闪断存活；恢复失败有界清理；身份、注册、索引和会话没有重复或孤立残留。

### H. 多跳 TLS 透明传输

- **执行：** 最后单独推进 15，按端点/认证设计、最小双节点路径、完整传输语义及部署兼容逐步完成。
- **边界：** 当前保留已知的节点间载荷泄露风险；其他批次均不以消除此风险作为完成前提。本批对握手、证书和功能链路的影响最大。
- **出批条件：** 满足 15 的端到端 TLS、认证、半关闭、取消和兼容验收，并完成相关配置与证书部署说明。

## 4. 各项实施范围与验收

### 01. 删除无生产调用的协议、字段和切片能力（A 批次已完成）

明确的清理对象：

- 无生产发起方的 `NodeLookup / NodeLocated / NodeError`，连同对应路由分支、编解码映射、测试和文档说明。
- `service.located` 中只用于校验/日志而无连接用途的控制端口：核对生产消费者后，删除冗余字段及其校验、传递和日志依赖。
- 当前无生产调用的 `PooledBuffer::slice()`，以及确认仅为切片存在的视图状态、双口径分支与测试。保留生产分配、正确释放和预算计费所需信息；不把“未来可能用到”作为保留理由。

验收：相应生产接口、不可达分支和无消费者字段被移除；只服务于已删除能力的测试一并删除或调整。不得仅删除测试后保留原能力，也不得为保留接口额外创造调用场景。后续若有实际需要，再以当时最小需求实现。协议、配置说明和样例与代码保持一致。

### 02. 合并单主控连接管理（A 批次已完成）

**当前冗余：** `NodeConnectionMgr` 只管理一个 `primary_`，围绕同一连接增加一层对象、转发接口和停止状态。

改进：合并 `NodeConnectionMgr` 与 `NodeConnection` 的所有权和生命周期，由一个对象直接承担启动、DNS、TLS 识别、重连、收发、停止与排空；简化 RelayAgent 对同一主连接的访问。删除原薄包装、转发接口及可合并的重复状态，不用新的管理器或适配器替换原包装。

验收：只保留一个清晰的主控连接所有者；连接识别、异常传播、重连和控制断线后的现有业务行为保持不变；DNS、握手和重试中均可停止排空。本项不顺带引入 14 的断线存活能力。

### 03. 合并重复配对管理

**当前冗余：** StreamPipeline 和 DatagramMgr 在准入、ID/票据、等待通知、关闭回收与远端 Flow 绑定上有重复骨架。

改进：逐段对照 LocalPair / RemotePair 的重复操作，复用稳定的准入、分配回滚、票据和生命周期逻辑，删除各自对应的重复实现。socket、UDP session/source/bindings、流/报文转发留在实际负责的传输实现中。按实际共性选择小型公共状态或函数，不预设公共继承基类，不以新增一套通用框架替代重复代码。

验收：明确列出被合并的重复段和被删除的原实现；TCP/TLS/UDP 的原有容量、认证、激活与回收行为保持正确。建立失败、重复 attach、关闭与等待唤醒均不重复分配、不泄漏、不重复释放。

### 04. 合并连续跨域操作

**当前冗余：** NodeSession 将 install、wait、bind、activate、bridge、close 拆成多次独立跨域协程调用，部分操作只有很小的状态变更。

改进：沿当前控制器流程标出真正需要返回 control_io 的节点，把无外部信令间隔的连续数据域操作合并，减少重复 co_spawn、协程包装与返回等待。peer 就绪同步、绝对建立期限、取消和执行域边界仍须保留；不能为了少一次投递从控制域直接修改数据域状态。

验收：给出修改前后的单跳/多跳跨域调用次数，删除被替代的细粒度接口或包装；既有接入时序、半关闭和停止排空保持正确。不以新增回调链、锁或适配层实现次数减少。

### 05. 内部状态强类型化

**当前问题：** NodeLinkMgr、Router 和 AgentSession 用 JSON 同时承担 wire 参数与运行时状态，重复解析和字段约束分散。

改进：先转换 NodeLinkMgr 的 Link/Flow 状态，再按需推进 Router、AgentSession；在协议边界集中解析和序列化。先按当前协议集中处理字段约束和解析，不等待后续协议或 TLS 改造；06 在此基础上精简 wire 字段。不引入两份长期同步的 JSON/结构体状态。

验收：核心状态推进不再反复解析路径和 transport；非法输入在边界明确拒绝；已确定的 wire 行为、幂等与错误传播保持正确。性能收益以测量为准。

### 06. 删除事务报文的重复路径载荷

**当前冗余：** Prepare 后的 Commit/Close 继续发送全量 path、addresses、links；确认报文再复制整份 endpoint 参数回传，并进行重复数组比对。

改进：保留建立所需的 Prepare 参数，后续阶段通过 epoch、flow_id、request_id、认证 source 和本地强类型状态关联事务；删除无需重复传输的数组、整份 JSON 克隆及对应重复解析。同步精简收发双方的校验，保留阶段、成员、幂等和冲突判断，明确未知事务 Close 的处理。Prepare 完成是内存安装，不当作已有持久化保证。

验收：记录各阶段删除的字段及修改前后报文大小；Commit/Close 和确认不再搬运整条路径；正常提交、回滚、重复、迟到、错误来源、未知事务关闭均保持正确。本项是协议载荷去冗余，不以增加服务目录或新事务体系作为前提。

### 07. 广播收敛与集群消息预算

**当前问题：** 正常业务准入与集群消息预算没有直接对应关系；查询广播放大。事务路径载荷已由 06 单独精简，本项重点减少消息数量和控制突发。不能仅凭静态的请求数乘节点数估算认定已发生队列溢出。

实施顺序：

1. 统计本地 Master 提交、远端 Slave 转发、成员通知各自经过的队列；它们并非全部经过 `outbound_channel_`。
2. 测量队列高水位、消息数量/字节数、每条建流事务的消息数，以及建流失败后关闭与确认的额外流量。覆盖共享 Link 已存在和需要新建两种情况。
3. Slave 的 `TopologyQuery` 改为定向 Master。对未命中服务查询合并在途请求、控制重试节奏；需要服务目录时，再明确注册、离线和迁移的一致性规则，不能无目录地直接改成任意节点单播。
4. 按消息预算控制新事务准入与分批推进，保证关闭、失败回滚和必要通知的容量；保持已有提交顺序，不引入同步重入或静默丢包。

验收：允许范围内的持续建流、服务缺失、成员变化及关闭突发均有可复现的消息预算；超预算业务尽早拒绝或有界等待；主动压满 Master 出站队列时仍按现有设计通知所有者并停机。消息收敛后，重复、迟到、错误来源与冲突请求仍被正确处理；区分减小单条报文字节数和降低队列中的消息条数。

### 08. 会话索引和准入计数

**当前问题：** RelayNode、Forwarder 和 ClusterRoom 存在 O(N) 查找；单条消息复杂度是 O(N)，不直接等于 O(N²)。

改进：以当前会话身份和生命周期为基线实施，不等待后续 UDP、primary 或 TLS 功能变化；后续功能调整同步维护索引。

- RelayNode 为 Agent 请求、端点和 peer Flow 身份建立必要索引，维护协议/多跳活跃计数。
- Forwarder 直接按 request 查找，为 Node、protocol、uuid 建立可表达多角色的索引；同一 Agent 的两种角色可能共享 uuid，不能简单映射为唯一会话。
- ClusterRoom 按 node_id 索引已加入成员，同时保留未完成加入的连接准入与排空管理。
- 主容器保持明确所有权，创建失败、关闭中、取消及完成时同步维护索引与计数。

验收：重复请求、冲突请求、同 Agent 双角色、迟到消息与取消范围保持正确；关闭未排空仍占额度；扩大并发规模后比较分派延迟与准入耗时，确认消除了对应全表扫描。

### 09. 缓冲区和复制优化

**当前问题：** 多跳 Stream 入口持有约 64 KiB 数组，随后按实际数据长度复制到池缓冲；TLS 复制也持有大数组。普通 TCP 复制当前是 32 KiB，不能统一称为 64 KiB。

改进：直接针对当前 Stream 入口选择读入池缓冲、合理分块或复用方案，不等待 15 的 TLS 改造。01 已按当前生产调用清理未使用切片；本项若确实需要调整有效长度，再实现有实际用途的最小接口，不恢复无人使用的通用切片设计。保留按真实持有分配计费，不能通过小视图低估大块内存。

验收：测量小包、连续大流量和慢接收端下的分配次数、复制字节、吞吐、RSS 与队列占用；确认未以更多在途大块内存换取较小协程帧。保持字节顺序、背压、取消和半关闭语义。

### 10. 拓扑快照 Master 授权（A 批次已完成）

**当前问题：** `handle_topology_snapshot()` 的 Master 来源校验被注释；格式校验不能替代发送方授权。

改进：在清理路由字段之前验证集群认证后写入的 `source` 等于当前 `topology_.master_id()`。保留 requester、session、request_id 及快照结构校验。

验收：正常 Master 响应仍可到达 Agent；其他已认证 Slave 构造的合法格式快照被拒绝，不能污染快照或终止正常请求；迟到、错误 requester 和已关闭会话的响应保持隔离。

### 11. 普通 Agent UDP forward 多客户端隔离

**当前问题：** 单个 `local_peer` 只锁定 IP，却不断覆盖端口，导致不同端口客户端回包串线，其他 IP 长期无法接入。

改进：按完整的本地源地址和端口维护关联；每个关联具有可确定的远端会话/回包归属。不能只把比较条件改成完整 endpoint 后继续只保留一个客户端。复用 Node 现有 session 机制前，确认 Producer 侧目标 socket 也能保持会话隔离；设置关联数量上限和创建节奏，纳入 07 的消息预算。

验收：同 IP 不同端口、不同 IP 的客户端并发请求时，回包各回各处；一个客户端退出或异常不影响其他客户端；容量耗尽不覆盖已有映射；服务下线和控制断开后正确清理。此项针对普通 Agent forward，不能将 proxy/SOCKS5 的行为直接视作同一实现。

### 12. 收尾期限与 UDP 回收

**当前问题：** 多跳 `bridge()` 完成后的 Finished 等待没有本地期限；UDP 没有 idle 回收。但现有 Flow 监视和控制失败能够触发清理，不能笼统表述为不可回收的永久泄漏。

改进：

- 只在本端桥接已完成、进入收尾确认时启动有限期限；对端 Finished 或关闭事件到达时结束。超时沿既有清理链路释放资源，保留原始结束原因。
- 不把“正常业务只有一方向 FIN、反方向仍有数据”的阶段直接按收尾超时强制中断。
- 基于 11 为 UDP 客户端关联维护双向活动时间和空闲回收；明确空包也属于活动。区分长期本地监听与客户端关联，回收关联不能触发无条件自动重建，否则无法释放配额。

验收：缺少 Finished 的场景在有限期限内释放会话和 Flow；正常半关闭仍能排空反向数据；UDP 空闲后释放关联，新包能够重新创建；服务离线与停止过程中无复活或重复释放。

### 13. 线程调度与命名（A 批次已完成）

**当前问题：** Linux 传输线程尝试设置接近最高等级的 `SCHED_RR`，成功后使用 `audio_thd` 名称。风险依赖权限和运行环境；现有打包 unit 未授予 `CAP_SYS_NICE`。

改进：默认使用普通调度，移除自动提升实时优先级的行为；按实际执行域设置简短线程名。没有测量依据时不新增调度调优配置。

验收：Agent/Node 不依赖实时调度权限启动；线程名符合职责；负载验证同时观察吞吐、control/data 执行域延迟与心跳，不只看传输吞吐。

### 14. primary 闪断与存活业务解耦

**当前问题：** primary 控制连接断开会取消所有 AgentSession；Node 一侧也依赖控制会话身份和离线清理。仅删除 Agent 的 cancel 调用不能完成解耦。

改进：先定义短暂失联宽限期、恢复后的身份重绑定、服务归属和业务终态同步，再同时调整两端生命周期。建立中的请求与已 ready 业务分开处理。真正的路径成员失效、Master epoch 变化或授权失效仍按协议清理；不将“控制连接重连”承诺为“Master 重启后原业务必然存活”。

验收：数据路径健康、epoch 和授权有效时，短暂 primary 连接闪断不会仅因断线就关闭 ready 业务；超出期限或恢复验证失败会有界清理；重连没有重复业务、重复注册所有权或永不回收的孤立会话。

### 15. 多跳 TLS 透明转发

**当前问题：** Agent 与接入 Node 各自建立 TLS。入口 Node 解密后将业务字节送入普通 TCP Flow；出口 Node 再通过另一条 TLS 会话发给对端 Agent。当前行为不满足透明转发目标，存在节点间业务载荷泄露风险。按当前安排放在最后处理，不作为前序清理与优化的前置依赖。

源码入口：[Agent 接入](../agent/src/agent_session.cpp)、[Node StreamPipeline](../node/src/pipeline_mgr.cpp)、[多跳控制器](../node/src/control_router_multi.cpp)、[TLS 业务复制](../protocol/src/xfr_channel.cpp)、[NodeLink](../protocol/src/lnk_channel.cpp)。

目标路径：

```text
Consumer Agent（TLS 加密）
  -> Ingress Node（转发密文字节）
  -> Relay Node（转发密文字节）
  -> Egress Node（转发密文字节）
  -> Producer Agent（TLS 解密）
  -> 本地目标服务
```

实施顺序：

1. **确定端点与认证。** 为两端 Agent 分配 TLS client/server 角色，明确对端身份与服务/会话的绑定规则。现有 Agent 配置主要信任 Node 的 Server CA，证书通常只有 `clientAuth`；不能直接假定现有证书可承担端到端 TLS server。现有共享 Agent 证书也不能单独证明某个具体服务的身份。调整证书用途、信任根、配置校验和签发工具时，保持 Agent/Node 控制通道的信任边界。
2. **确定接入与握手时序。** 先通过现有控制面授权、票据和接入流程建立可转发的字节通道，再在通道上进行 Agent 间 TLS 握手。分别定义“转发通道可用”和“业务 TLS 就绪”；避免 Agent 等待 `relay.ready` 才开始握手、Node 又等待握手完成才开始桥接的循环等待。
3. **完成最小双节点路径验证。** 接入 Node 只处理自己的接入认证和外层转发协议，不解析端到端 TLS 的业务 DATA/FIN。TLS 握手字节与后续 record 都经 Flow 按序传送。两端 Agent 负责加解密与业务半关闭。
4. **扩展完整行为。** 覆盖更多中继跳、双向限速与计数、超时取消、FIN 排空及异常退出；明确单节点 TLS 与多节点 TLS 的一致性和兼容边界。
5. **落实协议兼容与部署。** 明确版本或能力协商，不支持新语义的组合明确拒绝建立，不能静默退回当前会解密的路径。更新设计、证书文档、配置样例和相关 dashboard 展示。

验收：

- 两端 Agent 建立同一条 TLS 会话；Node 转发业务的路径不持有该会话的解密状态。
- 在受控测试中验证跨全部 NodeLink 重组后的业务载荷是端到端 TLS 字节流；结合代码路径和握手验证，不仅依靠“抓包未搜到明文”判断安全性。
- 无效或不匹配的对端认证失败，握手超时和失败后配额、socket、Flow 全部释放。
- 双向大流量、慢接收端、半关闭后反向排空、TLS 异常截断均符合既定语义。
- 外层 NodeLink 头与控制帧仍由 Node 处理；端到端 TLS 的机密性/完整性不被误称为外层 FIN/RESET 或路由元数据也已获得认证保护。
